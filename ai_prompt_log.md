# AI Prompt Log and Human Audit

## 1. Prompt used

The first draft of `schemas.py`, `extractor.py` and `fallback.py` was generated by an AI coding assistant from this prompt:

> You are a Staff AI Systems Engineer specializing in reliable programmatic LLM integration. I need an automated, fault-tolerant unstructured data extractor in Python 3.11+ that parses raw PDF text or HTML documents into strictly validated Pydantic v2 models.
>
> Requirements:
> - Models `LineItem`, `InvoiceExtraction` and `ExtractionResult` with the fields from the assignment (invoice number, vendor, date, line items, subtotal, tax, total, currency USD/EUR/GBP).
> - Field validators for messy dates like "12th of Oct, 2024", money strings like "$1,249.50" and currency symbols. A model validator that checks line items + tax = total within 0.02.
> - `extract_with_retry(raw_text, max_retries=3)`: structured decoding first, then a reflection re-prompt with the validation errors, then `json_repair`, then a dead-letter queue (DLQ). Return `SUCCESS`, `REPAIRED_VIA_REFLECTION` or `DLQ_FAILED` and never crash.
> - Use a local Ollama model through the OpenAI-compatible API. No API keys.

## 2. Summary of the first output

The draft had the right shape: three models, a retry loop, a reflection prompt, a `json_repair` step and a DLQ file. It looked complete, but when I ran it and read it line by line I found the problems below. The first one stopped the code from even importing.

## 3. Issues found and fixes

### Issue 1: Pydantic v1 syntax (`@validator`, `@root_validator`)

The prompt asked for Pydantic v2, but the draft used the old v1 decorators.

**Before (AI draft):**

```python
from pydantic import BaseModel, Field, validator, root_validator

@validator("invoice_date", pre=True)
def parse_date(cls, v):
    ...

@root_validator
def check_total(cls, values):
    items = values.get("line_items") or []
    ...
    return values
```

**What happened when I ran it** (Pydantic 2.14):

```
pydantic.errors.PydanticUserError: If you use `@root_validator` with pre=False (the default)
you MUST specify `skip_on_failure=True`. Note that `@root_validator` is deprecated and
should be replaced with `@model_validator`.
```

The file crashed on import. After a temporary patch, every `@validator` still printed a `PydanticDeprecatedSince20` warning.

**After (final code):**

```python
from pydantic import BaseModel, Field, field_validator, model_validator

@field_validator("invoice_date", mode="before")
@classmethod
def check_date(cls, value):
    return parse_messy_date(value)

@model_validator(mode="after")
def check_totals(self):
    items_sum = sum(item.line_total for item in self.line_items)
    ...
    return self
```

**Fix:** only v2 APIs: `field_validator`, `model_validator`, `model_validate()`, `model_dump_json()`.

### Issue 2: Context stuffing in retries

Every retry pasted the full document into the prompt again.

**Before (AI draft):**

```python
def build_reflection_prompt(raw_text, bad_output, error):
    return (
        "Your last answer was wrong.\n"
        f"Error: {error}\n"
        f"Your answer: {bad_output}\n"
        f"Here is the document again:\n{raw_text}\n"
        "Return fixed JSON only."
    )
```

With a long contract this makes each retry slower, and a small local model can lose the important part in all that text.

**After (final code):**

```python
def build_reflection_prompt(raw_text, bad_output, errors):
    snippet = make_context_snippet(raw_text, errors)   # max 1500 characters
    error_lines = "\n".join(f"- {e}" for e in errors)
    return (
        "Your previous JSON did not pass validation.\n\n"
        f"Validation errors (field: message):\n{error_lines}\n\n"
        f"Your previous JSON:\n{bad_output[:2000]}\n\n"
        f"Relevant part of the document:\n{snippet}\n\n"
        ...
    )
```

**Fix:** `make_context_snippet()` sends the start of the document plus only the lines that match the failed fields (for example "tax" or "total"). The retry messages replace the first long message instead of adding to it. The test `test_retry_prompt_does_not_resend_the_whole_document` checks this.

### Issue 3: Swallowed validation errors and all-None objects

**Before (AI draft):**

```python
class InvoiceExtraction(BaseModel):
    invoice_number: Optional[str] = None
    vendor_name: Optional[str] = None
    invoice_date: Optional[date] = None
    line_items: List[LineItem] = []
    total_amount: Optional[float] = None
    currency: Literal["USD", "EUR", "GBP"] = "USD"
...
except Exception as e:
    errors.append(str(e))
...
except Exception:
    write_dlq(raw_text, errors)
    return ExtractionResult(validated_data=InvoiceExtraction(), ...
                            execution_status="DLQ_FAILED")
```

Problems I found:

- `InvoiceExtraction()` with no data was valid. I tested it and got `{'invoice_number': None, 'vendor_name': None, 'invoice_date': None, 'line_items': [], 'subtotal': None, 'tax_amount': 0, 'total_amount': None, 'currency': 'USD'}`.
- A failed run still returned this empty object as `validated_data`, so downstream code could think it had real data.
- The total check was skipped when `total_amount` was `None` (`if values.get("total_amount") and ...`).
- `except Exception` also caught connection errors, so "Ollama is not running" would look like a bad invoice and go to the DLQ.
- Errors were saved as one long string, without the field location.
- `repair_json()` returned `{}` on any error.

**After (final code):**

```python
class InvoiceExtraction(BaseModel):
    invoice_number: str = Field(pattern=r"^[A-Za-z0-9][A-Za-z0-9\-/#]{2,29}$")
    vendor_name: str = Field(min_length=1)
    invoice_date: date
    line_items: List[LineItem] = Field(min_length=1)
    ...
    currency: Literal["USD", "EUR", "GBP"]

# ExtractionResult refuses half results
if self.execution_status == "DLQ_FAILED" and self.validated_data is not None:
    raise ValueError("DLQ_FAILED result cannot have validated_data")

# Only ValidationError and JSONDecodeError are caught, with loc and msg
except ValidationError as e:
    for err in e.errors():
        location = ".".join(str(part) for part in err["loc"]) or "(model)"
        errors.append(f"{location}: {err['msg']}")
```

**Fix:** all required fields are required, a failure returns `validated_data=None`, every error is logged as `attempt N | field: message`, and `OllamaNotRunningError` is raised to the UI instead of being hidden.

### Issue 4: Fragile date and type coercion

**Before (AI draft):**

```python
@validator("invoice_date", pre=True)
def parse_date(cls, v):
    if isinstance(v, str):
        return datetime.strptime(v, "%Y-%m-%d").date()
    return v

@validator("subtotal", "tax_amount", "total_amount", pre=True)
def clean_money(cls, v):
    if isinstance(v, str):
        return float(v.replace("$", "").replace(",", ""))
    return v
```

What I saw when I tested it:

```
invoice_date='12th of Oct, 2024'
-> time data '12th of Oct, 2024' does not match format '%Y-%m-%d'

currency='$'
-> Input should be 'USD', 'EUR' or 'GBP'
```

Also, `unit_price` and `line_total` in `LineItem` had no money cleaner, and `€` or `£` amounts were not handled.

**After (final code):**

```python
def parse_messy_date(value):
    # ISO first, then remove "th", "of" and commas, then try a few formats
    ...
    text = re.sub(r"(\d+)(st|nd|rd|th)\b", r"\1", text, flags=re.IGNORECASE)
    text = re.sub(r"\bof\b", " ", text, flags=re.IGNORECASE)
    ...
    raise ValueError(f"could not read the date '{value}', use YYYY-MM-DD")

def clean_money(value):
    # removes $ € £, commas and currency codes, raises an error if it is not a number
    ...

CURRENCY_MAP = {"$": "USD", "€": "EUR", "£": "GBP", ...}
```

**Fix:** one shared date pre-parser (`mode="before"`), one shared money cleaner used by `LineItem` and `InvoiceExtraction`, and a currency map. Bad text is a clear error, never a silent default. Tests: `test_messy_values_are_cleaned` and `test_bad_money_text_is_an_error_not_zero`.

### Smaller issues also fixed

- The draft did not use `instructor` or a JSON schema. It only said "Extract the invoice as JSON". The final code uses `instructor` in JSON mode with `response_model=InvoiceExtraction`.
- The model name and URL were hard coded. Now they come from `OLLAMA_MODEL` and `OLLAMA_BASE_URL`.
- The wait between retries was always 1 second. Now it grows (1s, 2s, 4s).
- The LLM client was created at import time, so tests could not mock it. Now the LLM is a function passed into `extract_with_retry(llm=...)`.
- There was no way to turn the reflection loop off. Now there is a `reflection` flag and a toggle in the UI.

## 4. Found while testing with the real model

This was not in the AI draft. I found it when I ran the pipeline with `llama3.2:3b` on a grocery list (not an invoice). The model invented an invoice (`"invoice_number": "Grocery-123456789"`) with prices that were not in the text. The fake invoice passed every schema rule and the pipeline returned `SUCCESS` on attempt 1.

**Fix:** `check_grounding()` in `extractor.py` checks that the invoice number and the total really appear in the document. If not, the errors go into the reflection loop like any other error. After the fix, the same grocery list ended as `DLQ_FAILED` after 3 attempts. Test: `test_invented_invoice_is_not_accepted`.
